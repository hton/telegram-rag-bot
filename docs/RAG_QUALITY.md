## Методология тестирования

### Критерии оценки релевантности

Каждый ответ оценивается по трём категориям:

- ✅ **Релевантный** - ответ полностью соответствует вопросу, источники содержат нужную информацию
- ⚠️ **Частично релевантный** - ответ частично соответствует, но есть недостатки (неполная информация, не тот тип продукта)
- ❌ **Нерелевантный** - ответ не соответствует вопросу, источники неправильные

### Оценка по критериям

1. **Точность продукта** - правильный ли продукт найден (VMmanager ≠ IPmanager ≠ BILLmanager ≠ DCImanager)
2. **Точность типа** - правильный ли тип продукта (Hosting ≠ Infrastructure ≠ ФСТЭК)
3. **Точность версии** - правильная ли версия (5 vs 6)
4. **Специфичность** - соответствует ли уровень детализации (уровень логирования vs логи)
5. **Полнота** - содержит ли ответ всю необходимую информацию

## Известные проблемы

### 1. Специфичность терминов (вопросы 5, 6)

**Проблема:** Система находит общие статьи вместо специфичных.

**Примеры:**
- "Уровень логирования" → находит статьи про "логи" в целом
- "Параметр БД" → находит статьи про UI настройки

**Причина:**
- В базе знаний нет документов с точным описанием уровней логирования
- В базе знаний нет документов со схемой БД

**Решение:**
- Проверить наличие документации в источнике
- Добавить недостающую документацию в базу знаний

### 2. Типы продуктов при общих вопросах (вопросы 2, 3)

**Проблема:** Без указания типа в вопросе система фокусируется на Hosting версиях.

**Примеры:**
- "Как установить VMmanager" → находит VMmanager Hosting
- "Как установить DCImanager" → находит DCImanager Hosting

**Причина:**
- В базе знаний больше документов про Hosting версии
- Vector Search находит наиболее популярные документы

**Решение (отложено):**
- Реализовать уточняющие вопросы для generic запросов
- Добавить метаданные (product_type) в базу данных
- Использовать условную фильтрацию по метаданным

### 3. Vector Search как bottleneck

**Проблема:** Reranker может выбрать только из того, что нашёл Vector Search.

**Причина:**
- Vector Search работает на семантической близости без учёта метаданных
- top_k=10 может быть недостаточно для сложных запросов

**Возможные решения:**
- Увеличить top_k для Vector Search (больше кандидатов для Reranker)
- Гибридный поиск (Vector + BM25)
- Добавить metadata filtering в Vector Search

## Планы улучшений

### Краткосрочные (1-2 недели)

1. ✅ **Улучшить промпты** - ЗАВЕРШЕНО (2025-12-30)
   - Результат: +8% релевантности

2. ⏳ **Проверить полноту базы знаний**
   - Проверить наличие документов про уровни логирования
   - Проверить наличие схемы БД в документации
   - Добавить недостающие документы

3. ⏳ **Увеличить top_k для Vector Search**
   - Текущее значение: 10
   - Предлагаемое: 15-20
   - Даст больше кандидатов для Reranker

### Среднесрочные (1-2 месяца)

1. ⏳ **Добавить метаданные в базу данных**
   - Поле `product_name` (VMmanager, DCImanager, BILLmanager, IPmanager)
   - Поле `product_type` (Hosting, Infrastructure, ФСТЭК)
   - Поле `product_version` (5, 6)

2. ⏳ **Реализовать условную фильтрацию**
   - Извлечение сущностей из вопроса (product, type, version)
   - Применение фильтров только когда сущности найдены
   - Широкий поиск для generic вопросов

3. ⏳ **Уточняющие вопросы в Telegram Bot**
   - Определение generic вопросов
   - Интерактивные кнопки для уточнения
   - Объединение исходного и уточняющего вопросов

### Долгосрочные (3+ месяца)

1. ⏳ **Гибридный поиск (Vector + BM25)**
   - Комбинирование семантического и лексического поиска
   - Улучшение точности для специфичных терминов

2. ⏳ **Более мощный Reranker**
   - Использование специализированных reranker моделей
   - Fine-tuning на собственных данных

3. ⏳ **A/B тестирование**
   - Автоматическое тестирование на наборе вопросов
   - Отслеживание метрик релевантности
   - Регрессионное тестирование при изменениях

## Как воспроизвести тестирование

### Подготовка

1. Убедитесь что API запущен:
   ```bash
   curl http://localhost:8080/health
   ```

2. Подготовьте список вопросов в `/tmp/test_questions.json`

### Запуск тестирования

```bash
# Скрипт тестирования
/tmp/test_rag.sh
```

### Результаты

- `/tmp/rag_test_results.md` - источники для каждого вопроса
- `/tmp/comparison_results.md` - сравнение с предыдущими результатами

### Анализ результатов

Для каждого вопроса проверьте:

1. **Правильный ли продукт?** (VMmanager/DCImanager/BILLmanager/IPmanager)
2. **Правильный ли тип?** (Hosting/Infrastructure/ФСТЭК)
3. **Правильная ли версия?** (5 vs 6)
4. **Соответствует ли уровень детализации?**
5. **Полный ли ответ?**

Оцените каждый ответ как:
- ✅ Релевантный
- ⚠️ Частично релевантный
- ❌ Нерелевантный
